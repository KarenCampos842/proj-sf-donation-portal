# Story Tracking Board

Tracking of the 44 user stories of **proj-sf-donation-portal** (SF Vibe Lab, UADY x Salesforce) by milestone and workstream. Cut-off date: **2026-11-10**, the day Delivery 1 is due (23:59, Mérida time). Figures below were re-read from GitHub on that day.

- **Source of truth for workflow status:** the GitHub Projects board ([Project 13](https://github.com/users/KarenCampos842/projects/13)): Backlog → Ready → In progress → In review → Done. This table reflects it at the cut-off and does not change it.
- **Stories, acceptance criteria (AC), assignees and open/closed state:** the [GitHub Issues](https://github.com/KarenCampos842/proj-sf-donation-portal/issues). Owners are the assignees of each issue.
- **Project status and issue state are different things.** An issue can be closed while its Project status is not Done, and a Done story is not automatically formally accepted. Both are shown side by side in the “Status” column.
- **Story names:** English translations of the Spanish GitHub issue titles. The issue links lead to the original Spanish titles and acceptance criteria, which this document does not modify. GitHub milestone names are “E1 - Primera entrega” and “E2 - Segunda entrega”.
- **Workstreams:** A = payments (Rodrigo Colli), B = public portal and Salesforce objects (Karen Elizabeth Campos), C = internal operation, security and data model (Alan Pérez Romero), as in `docs/contributions.md`. GitHub has no workstream field, so it is derived from the owner.
- **Implemented is not the same as accepted:** a story is accepted only when all its acceptance criteria, including negative ones, have evidence (demo, video or screenshot) without breaking M1–M3 (see the Definition of Done in `README.md`). TAC are not a condition. This table does not declare any story formally accepted.

## Update rules

1. **Hours:** recorded only when verifiable data exists per story. Until then the cell says “Pending”. AI Log time-saving estimates are not hours spent and are not used here.
2. **Evidence:** only commits, PRs, tests, screenshots, documents or AI Log entries that exist. Implementation evidence (code, tests, deployments) is kept apart from acceptance evidence (screenshots or notes per AC). Evidence folders that are not tracked in Git are written as plain paths, marked “local only”, and are not linked, because the link would be broken on GitHub.
3. **Status:** copied from Project 13. Differences between the Project status and the issue state are listed under “Inconsistencies”.
4. **Owners:** the assignees of each issue; not changed here.
