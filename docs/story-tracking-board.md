# Story Tracking Board

Tracking of the user stories of **proj-sf-donation-portal** (SF Vibe Lab, UADY x Salesforce) by milestone and workstream. Cut-off date: **2026-11-17**, the day Delivery 2 is due (23:59, Mérida time). Figures below were re-read from GitHub on that day (Issues, [Project 13](https://github.com/users/KarenCampos842/projects/13) and merged pull requests). The previous cut-off was 2026-11-10, Delivery 1.

- **Source of truth for workflow status:** the GitHub Projects board ([Project 13](https://github.com/users/KarenCampos842/projects/13)): Backlog → Ready → In progress → In review → Done. This table reflects it at the cut-off and does not change it.
- **Stories, acceptance criteria (AC), assignees and open/closed state:** the [GitHub Issues](https://github.com/KarenCampos842/proj-sf-donation-portal/issues). Owners are the assignees of each issue.
- **Project status and issue state are different things.** An issue can be closed while its Project status is not Done. Both are shown side by side in the “Status” column. At this cut-off every closed issue is Done in Project 13 and every Done story is closed.
- **Story names:** English translations of the Spanish GitHub issue titles. The issue links lead to the original Spanish titles and acceptance criteria, which this document does not modify. GitHub milestone names are “E1 - Primera entrega” and “E2 - Segunda entrega”.
- **Workstreams:** A = payments (Rodrigo Colli), B = public portal and Salesforce objects (Karen Elizabeth Campos), C = internal operation, security and data model (Alan Pérez Romero), as in `docs/contributions.md`. GitHub has no workstream field, so it is derived from the owner.
- **Scope:** 44 stories are in scope: the 22 Delivery 1 stories, the 21 Delivery 2 stories and PAY-08, which was added after the original backlog and has no milestone. **DON-26 is out of scope** (the team decided it will not be built); it is listed at the end and excluded from every count. Issue #54 is a bug found while collecting Delivery 1 evidence, not a story; it is also excluded from the counts.
- **Implemented, closed and accepted are different:** a story is accepted when its acceptance criteria are met and evidenced without breaking M1–M3 (see the Definition of Done in `README.md`). TAC are not a condition. For Workstreams A and B the issue is closed, Done in Project 13, every AC box is ticked and the “Evidence” section of the issue is filled. For Workstream C the stories are Done and closed in Project 13, but the AC boxes and the “Evidence” section of their issues still hold the original placeholder (see “Inconsistencies”); this board reports their Project 13 status and does not tick anything on their behalf.

## Update rules

1. **Hours:** recorded only when verifiable data exists per story. Until then the cell says “Pending”. AI Log time-saving estimates are not hours spent and are not used here.
2. **Evidence:** only commits, PRs, tests, screenshots, documents or AI Log entries that exist. Implementation evidence (code, tests, deployments) is kept apart from acceptance evidence (screenshots or notes per AC). Every evidence folder listed below is tracked in `main` and linked with a relative path.
3. **Status:** copied from Project 13. Differences between the Project status and the issue state are listed under “Inconsistencies”.
4. **Owners:** the assignees of each issue; not changed here.
5. **Dates:** merge dates are the GitHub merge dates (UTC).
